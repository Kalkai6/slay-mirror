# Slay Mirror — Demo Script

## Before you start (do this 10 minutes before your demo)
1. Open Anaconda Prompt, start the backend:
   cd /d D:\SlayMirror\backend
   conda activate D:\SlayMirror\envs\vton
   uvicorn main:app --reload --port 8000
2. Open a second terminal, start the frontend:
   cd /d D:\SlayMirror\frontend
   npm run dev
3. Open http://localhost:5173 in your browser, confirm the catalog loads.
4. Have a full-body photo ready on your laptop (or phone, airdropped/transferred).

---

## Demo Flow (~5 minutes)

**1. Introduce the project (30 sec)**
"This is Slay Mirror, a demo fashion platform with real AI-powered virtual
try-on. Users can browse products, add to cart, and see themselves wearing
an item before buying — generated by a real pretrained AI model running
on my own GPU, not a mockup."

**2. Show the catalog (20 sec)**
Point out the two products, real photos, categories, prices.

**3. Add to cart (15 sec)**
Click "Add to Cart" on one item. Point out the cart counter updating live.

**4. Open the cart (15 sec)**
Click the Cart badge. Show quantity controls, remove button, total price.

**5. Click Try On (15 sec)**
Click "Try On" next to the item. Explain: "This takes you to the try-on
page for this specific garment."

**6. Upload a photo and generate (90 sec — talk while it loads)**
Upload your photo, click Try On.
WHILE WAITING, explain the pipeline:
"Behind the scenes, this is calling my own FastAPI backend, which runs
three AI steps: DWPose detects my body pose, FASHN's human parser
segments my body regions, and then a diffusion model generates the final
image — replacing just the clothing region while preserving my face, pose,
and background. This typically takes 60-90 seconds on my RTX 4050."

**7. Show the result (20 sec)**
Point out face/pose/background preservation. Click Download Result.

**8. Mention what's reused vs. built (30 sec)**
"The AI model itself — FASHN VTON v1.5 — is an existing, pretrained,
open-source model under Apache-2.0 license. I didn't train it. What I built
is the entire website, the cart system, and the FastAPI backend that
connects the website to the model."

**9. Mention known limitations if asked (don't volunteer unless asked)**
"I did thorough testing and found two honest limitations: the model can
sometimes slightly alter body proportions, and it doesn't reject non-person
images with a clean error - both documented limitations of this class of
model, which I plan to investigate further."

## If something goes wrong live
- Generation fails/errors: "This is a live AI model, occasionally it can
  fail on an edge case - let me show you a result I generated earlier
  instead" (keep a saved result image ready as backup).
- Backend crashed: have it already running before your professor arrives,
  don't start it live if avoidable.
